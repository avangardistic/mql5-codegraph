# Implementation Plan: Intelligence Kernel

**Branch**: `main` | **Date**: 2026-07-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-intelligence-kernel/spec.md`

## Summary

Introduce a read-only, backend-neutral Intelligence Kernel above the canonical `CodeGraph`. The kernel
builds one immutable index per graph snapshot and owns deterministic matching, bounded context and
impact traversal, evidence-ranked directed paths, diagnostics, and structural context packages. CLI
and Web migrate behind compatibility projectors that preserve every existing command, route, JSON
shape, error, and default; new normalized operations use the separately versioned `1.0.0` contract.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**: Python standard library only; existing web/dashboard dependencies remain unchanged

**Storage**: Existing canonical graph JSON; immutable in-memory indexes derived per graph snapshot

**Testing**: `unittest`, golden JSON contracts, adapter conformance vectors, deterministic synthetic benchmark

**Target Platform**: Windows-first local CLI and loopback dashboard; portable Python core

**Project Type**: Python library/CLI with local HTTP and static web adapters

**Performance Goals**: At least 95% of a fixed 200-request mix complete below one second on a documented
10,000-node/approximately 40,000-edge reference graph after index construction

**Constraints**: Offline, read-only source analysis, deterministic serialization, no parser/backend coupling,
bounded traversal, no runtime dependency addition, and exact legacy CLI/Web compatibility

**Scale/Scope**: One local graph snapshot; 10,000 reference nodes; query, context, impact, diagnostics,
directed path, and context-package operations; guardrail catalogs, MCP stabilization, and prompt rendering deferred

## Constitution Check

*GATE: Passed before research and re-checked after Phase 1 design.*

- **MQL5 semantic fidelity — PASS**: Kernel consumes existing MQL5-aware nodes and edges and never
  reclassifies runtime or inferred relationships as source calls.
- **Evidence-backed graph — PASS**: Every returned relationship and path hop retains direction,
  origin, confidence, location, and explicit evidence state.
- **Deterministic CLI contracts — PASS**: Legacy outputs remain frozen; normalized v1 uses canonical
  sorting and explicit contract-version validation.
- **Test corpus before claims — PASS**: Golden fixtures, malformed/ambiguous cases, cycles, bounds,
  adapter conformance, and deterministic synthetic graphs are required before capability claims.
- **Small composable core — PASS**: `CodeGraph` remains backend-neutral; Kernel imports no CLI, Web,
  MCP, visualization, database, parser, or exporter modules.
- **Technical constraints — PASS**: Local-only, no source mutation, no generated data committed,
  and incompatible public changes require a new contract major.

**Post-design check**: PASS. No constitution exception or complexity waiver is required.

**Structure Decision**: Add one cohesive `intelligence` package between the canonical graph and all
semantic adapters. Pure exporters continue consuming `CodeGraph` directly. Filesystem-safe source
reading and analysis-job state remain Web concerns; the kernel may accept an optional evidence probe
protocol but never assumes a repository root.

## Delivery Sequence

1. Characterize and freeze legacy CLI/Web behavior with golden tests.
2. Add v1 models, validation, immutable indexes, stable errors, and deterministic serialization.
3. Implement matching, traversal, path, diagnostics, and context-package operations behind the kernel.
4. Migrate legacy adapters through compatibility projectors while dual-running conformance vectors.
5. Add the versioned CLI namespace and `/api/v1/intelligence/*` HTTP routes.
6. Run determinism, evidence-state, negative, regression, reference-fixture end-to-end, and opt-in
   reference-scale gates.

No deprecation or removal occurs in feature 003. `CodeGraph.find_nodes()`, `neighborhood()`, and
`upstream_impact()` remain compatibility helpers until a later versioned migration explicitly removes them.

## Complexity Tracking

No constitution violations. The package split is justified by separate contract, indexing, matching,
traversal, path-ranking, and context-selection responsibilities; it does not add a second analysis engine.
